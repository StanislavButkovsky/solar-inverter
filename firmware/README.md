# Прошивка модуля мониторинга

ESP32 читает DALY BMS и инвертор и показывает их состояние веб-страницей
в локальной сети. Настройка сети — два способа: точка доступа и терминал по USB;
точка доступа с формой в браузере.

Проверено на плате ESP32-D0WD-V3, 4 МБ флеш, без PSRAM (WROOM), USB-мост CP2104.

## Цели сборки

Одна кодовая база на три устройства и сборка разведки. Различаются ровно два
файла — профиль и транспорт, — всё остальное общее.

| Окружение | Устройство | Как читает инвертор | Занято флеша |
|---|---|---|---|
| `esp32dev` | обычный ESP32 (WROOM) | Bluetooth через донгл Eybond | 65 % от 1,9 МБ |
| `esp32s3-hs35` | ESP32-S3 | USB через мост CH340, Megatec Q1 на 9600 | 38 % от 3,3 МБ |
| `esp32s3-asterion` | ESP32-S3 | USB, текстовый протокол Voltronic | 38 % от 3,3 МБ |
| `esp32s3-probe` | ESP32-S3 | не опрашивает: разведка USB нового инвертора | 38 % от 3,3 МБ |

```bash
pio run -e esp32dev                                     # сборка первого
pio run -e esp32dev -t upload --upload-port /dev/ttyUSB0
pio run -e esp32s3-hs35                                 # сборка второго
pio run -e esp32s3-asterion                             # сборка третьего
pio run -e esp32s3-probe                                # разведка USB
pio device monitor -b 115200                            # терминал
```

Без `-e` собираются все цели. Выбор профиля и транспорта идёт по флагам
`TARGET_HS35` (транспорт USB, профиль Megatec), `TARGET_ASTERION` (профиль
Voltronic), `TARGET_MUST` (профиль MUST по Modbus, ни одна цель его пока не
включает) и `USB_PROBE` (разведка вместо опроса) — не
через `#ifdef` по всему коду, а на уровне того, какие файлы вообще попадают
в сборку: каждый `profile_*.cpp` и `inv_*.cpp` целиком закрыт своим условием.

### Почему так, а не два репозитория

Показ, журнал, сеть, кнопка, темы, ярлык, API — одинаковые. Разделив проект
на части, каждую опечатку в вёрстке пришлось бы чинить в каждой копии, и через
месяц копии разошлись бы. Разделение проведено там, где различия настоящие:
по проводу и по карте регистров.

## Сеть

**Основной режим — клиент домашней сети.** Точка доступа поднимается только когда
клиентом подключиться не удалось, чтобы модуль не превращался в кирпич, если роутер
выключили, он переехал или на нём сменили пароль.

| Состояние | Когда |
|---|---|
| STA | сеть задана и подключена — обычная работа |
| AP | сеть не задана вовсе, ждём настройки |
| AP + STA | сеть задана, но подключиться не вышло: точка доступа открыта для настройки, и параллельно раз в 30 с идут попытки подключиться |

После успешного подключения точка доступа гасится не сразу, а через две минуты —
чтобы тот, кто настраивает модуль с телефона, успел увидеть выданный адрес.
Если сеть теряется во время работы, точка доступа поднимается снова.

### Первый запуск

Настроек в NVS нет, поэтому поднимается точка доступа:

```
SSID    solar-setup
пароль  12345678
адрес   http://192.168.4.1
```

Дальше любым из двух способов задать домашнюю сеть — на этой странице
или через терминал:

```
> wifi scan
> wifi set МояСеть мойпароль
```

Модуль перезагрузится и станет клиентом. Страница будет доступна по
`http://solar.local` и по выданному IP. Адрес полезно закрепить за MAC-адресом
модуля на роутере: планшет держит его закладкой, и она не должна протухать.

Только 2,4 ГГц — у ESP32 нет приёмника на 5 ГГц.

## Как подключиться к батарее

Механика есть, дело только в расстоянии: Bluetooth должен добивать от модуля до
батареи. Мерить — карточкой «Поиск батареи» на странице либо командой `ble scan`.

| Уровень сигнала | Что это значит |
|---|---|
| −60 дБм и выше | отлично |
| −80 дБм | рабочий уровень |
| −90 дБм | на грани, связь будет рваться |
| ничего не видно | не добивает |

Карточка показывает всё, что модуль слышит, отсортированное по уровню сигнала, и
помечает похожее на DALY (сервис `FFF0` либо имя `DL-…`). Кнопка «привязать»
запоминает MAC — после этого модуль цепляется только к этой батарее. Если MAC
не задан, он подключится к первому подходящему устройству, что удобно на столе
и плохо там, где батарей несколько.

Модуль можно носить: питание от повербанка, телефон подключается к точке доступа
`solar-setup`, и та же карточка работает без домашней сети. Так ищется место установки.

**Прогноз без модуля:** встать с телефоном туда, где он будет стоять, и открыть
официальное приложение DALY. Мощность передатчика у телефона сопоставима, так что
если приложение уверенно держит связь оттуда — удержит и модуль.

### Порядок первого подключения на месте

1. **Выключить демо-режим** — кнопкой на жёлтой плашке или командой `sim off`.
   Он живёт в NVS и переживает перезагрузку, так что рядом с настоящей батареей
   легко залипнуть на нарисованных цифрах и долго не понимать, почему они
   не сходятся с приложением.
2. **Закрыть официальное приложение DALY на телефоне.** Донгл держит ровно одно
   BLE-соединение: пока в нём висит телефон, модуль не подключится, и наоборот.
3. Подать питание. Дальше зависит от того, есть ли на месте сеть:

   * **Сеть та же, что дома** — модуль войдёт в неё сам, ничего делать не надо.
     Страница по прежнему адресу.
   * **Сеть другая** — модуль не найдёт сохранённую, поднимет точку доступа
     `solar-setup` (пароль `12345678`) и продолжит попытки в фоне. Подключиться
     к ней телефоном, открыть `http://192.168.4.1`, «Настроить сеть».
   * **Сети нет вообще** — и не нужна. Точки доступа модуля достаточно: телефон
     подключается к `solar-setup`, страница работает целиком, батарея читается.
     Внешняя сеть нужна только чтобы смотреть показания с планшета из дома.

   Питание — повербанк. Модуль берёт 100–150 мА, и банки с отсечкой по малому току
   иногда на таком гаснут; если гаснет, взять зарядку в розетку или банк без
   автоотключения.
4. Карточка «Поиск батареи» → «Искать 5 секунд». Батарея должна появиться
   с пометкой «похоже на DALY». Нажать «привязать».
5. Смотреть карточку «Канал связи»: счётчик принятых кадров растёт, кадров
   с ошибкой и разрывов — ноль. Пары минут наблюдения достаточно, чтобы понять,
   держится связь или сыпется.
6. **Сверить показания с официальным приложением.** Нажать «Отпустить батарею
   приложению на 10 минут», посмотреть в приложении, вернуться. Сверять: SOC,
   суммарное напряжение, ток и особенно его знак, напряжения ячеек и номера
   минимальной с максимальной, остаточную ёмкость. Это единственная проверка
   смещений полей, которую нельзя сделать заранее.

### Как узнать адрес после смены сети

Меняете сеть — модуль перезагружается, уходит в другую сеть и получает адрес
от чужого DHCP. Старая вкладка мертва, и адрес взять неоткуда. Поэтому после
любой смены сети (из веба или командой `wifi set`) модуль на
следующей загрузке **держит свою точку доступа десять минут**, даже если в сеть
вошёл успешно. Четыре способа узнать адрес, по надёжности:

1. Подключиться телефоном к `solar-setup` (пароль `12345678`), открыть
   `http://192.168.4.1` — новый адрес написан прямо на странице. Работает всегда.
2. `http://solar.local` — если устройство понимает mDNS. iOS и macOS понимают,
   Android — как повезёт.
3. Список клиентов на роутере: имя `Solar-…`, MAC начинается на `20:9b:a9`.

Адрес стоит закрепить за модулем на роутере — тогда закладка на планшете
перестанет протухать.

### Почему точка доступа не отваливается во время настройки

У ESP32 одна антенна, и точка доступа с клиентом обязаны жить на одном канале.
Каждая попытка подключиться к сохранённой сети уводит канал за собой — телефон
настройщика в этот момент отваливается, ровно когда он что-то настраивает.
Поэтому пока к точке доступа кто-то подключён, попытки STA приостановлены;
предел паузы десять минут, на случай забытого телефона.

### Если батарея не находится

* Устройство видно, но без пометки «похоже на DALY» — у донгла другой профиль.
  Снять дамп сервисов через nRF Connect и сверить с `FFF0/FFF1/FFF2`.
* В эфире вообще пусто — проверить, не включён ли на BMS облачный или Wi-Fi
  режим: он полностью отключает Bluetooth.
* Устройство видно, привязка есть, но соединение не встаёт — почти всегда это
  телефон, который молча держит канал: у донгла соединение только одно.

## Показ без батареи

Батарея может быть далеко, а интерфейс показать надо. Демо-режим генерирует
правдоподобную сборку 14S NMC с зарядом, разрядом и балансировкой:

```
> sim on
```

В интерфейсе при этом висит жёлтая плашка «Демонстрационные данные» — спутать
с настоящими показаниями невозможно. Выключается `sim off`.

## Кнопка BOOT

Вторая кнопка на плате (не EN, та сбрасывает контроллер) используется как
пользовательская — она переводит Wi-Fi в режим точки доступа.

| Действие | Что происходит |
|---|---|
| короткое нажатие | включить или выключить точку доступа `solar-setup` |
| удержание 8 секунд | сброс всех настроек и перезагрузка |

Точка доступа, поднятая кнопкой, сама не гаснет: её включают именно тогда, когда
до модуля иначе не достучаться. Повторное нажатие возвращает обычный режим
клиента — но только если модуль в этот момент в сети, иначе выключать её некуда
и он остался бы недоступен совсем.

Светодиод на плате горит, пока точка доступа поднята, и часто мигает, если
кнопку держат дольше восьми секунд — это предупреждение о сбросе. Отпустить
раньше безопасно, действие выбирается в момент отпускания.

**Два ограничения GPIO0.** Первое: её нельзя держать нажатой при подаче питания
или сбросе — в этот момент она переводит чип в режим прошивки, и программа
не стартует.

Второе неочевидное: **эта нога сидит на схеме автосброса платы**, и любая
программа, открывшая последовательный порт, прижимает её к земле на всё время
работы. Для прошивки это выглядит как нажатая кнопка. Поэтому нажатия дольше
двадцати секунд игнорируются — человек столько не держит, а залипшая линия
держит сколько угодно. Без этого ограничения каждая сессия отладки заканчивалась
сбросом настроек.

Светодиод предполагается на GPIO2 — так на большинстве плат DevKit, но не на всех.
Если не мигает, значит на этой плате его там нет: логика кнопки от этого
не страдает, проверять придётся по терминалу и по странице.

## Команды терминала

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `status` | состояние сети и батареи целиком |
| `wifi scan` / `wifi set <ssid> <pass>` / `wifi status` | сеть |
| `ble scan` | что видно в эфире, с пометкой похожих на DALY |
| `ble mac <mac>` | привязать конкретную батарею (пусто — искать самому) |
| `ble release <мин>` | отпустить батарею официальному приложению |
| `sim on` / `sim off` | демо-данные |
| `poll <мс>` | пауза между запросами к BMS, по умолчанию 300 |
| `usb` | отчёт разведки USB инвертора (только сборки под S3) |
| `reboot`, `factoryreset` | перезагрузка, сброс настроек |

На ESP32-S3 терминал выведен на разъём **COM** платы (`ARDUINO_USB_CDC_ON_BOOT=0`):
нативный USB чипа работает хостом, в него включается инвертор.

## Обновление по сети

Плата обновляется без кабеля, под паролем модуля (`webpass <пароль>` в
терминале или «Настройки» → «Обновление прошивки»; пока пароля нет —
обновление по сети выключено). Два пути:

* **с компьютера** (ArduinoOTA, порт 3232; компьютер в той же сети):
  ```bash
  pio run -e esp32s3-hs35
  ~/.platformio/penv/bin/python ~/.platformio/packages/framework-arduinoespressif32/tools/espota.py \
    -i <адрес платы> -I <адрес компьютера> -P 34567 -a '<пароль>' \
    -f .pio/build/esp32s3-hs35/firmware.bin
  ```
* **со страницы** — файл `firmware.bin` кусками по 8 КБ (`/api/ota/begin`,
  `/part`, `/end`).

Почему кусками: одним файлом загрузка рвалась — Update стирает флеш блоками
по 64 КБ, на это время замирает приём Wi-Fi, а WebServer ждёт данных не
дольше 5 с. Кусок принимается в память целиком и пишется уже после приёма.
Смещение и пароль куска — в заголовках `X-Off` и `X-Pass`: у запросов с
сырым телом WebServer параметры адреса не разбирает и отдаёт оставшиеся от
прошлого запроса.

**Откат.** Новая прошивка помечает себя годной, только проработав 90 с без
сбоя; перезагрузка раньше — загрузчик вернёт прежнюю. Метка сборки (время и
коммит) — на странице и в `status`.

## Память

На HS35 (ESP32-S3 N8R2) 21.10.2026 минимум свободной памяти доходил до
**140 байт** — на рукопожатии TLS бота; обновлению не нашлось 4 КБ подряд.
Что помогло, по убыванию:

| Мера | Свободно / минимум |
|---|---|
| исходно (Bluetooth, бот держит TLS) | 50 КБ / 0,1 КБ |
| бот закрывает TLS между опросами | 64 КБ / 0,1 КБ |
| Bluetooth не поднимается без привязанной батареи | 130 КБ / 68 КБ |
| NimBLE убран из сборки (`NO_BLE`) | 165 КБ / 105 КБ |
| PSRAM включена (`BOARD_HAS_PSRAM`, `dio_qspi`) | 183 КБ сразу после включения |

`status` и `/api/state` показывают свободную память, крупнейший кусок и
минимум за работу — утечка видна со временем; `status` — ещё и PSRAM.
PSRAM модуля (2 МБ, QSPI) долго считалась «не поднимается», а её просто
не просили: у `esp32-s3-devkitc-1` в PlatformIO PSRAM выключена, и без
`-DBOARD_HAS_PSRAM` ядро её не ищет. Включена только в `esp32s3-hs35` —
у Asterion другая плата, не проверялась. Крупные выделения памяти ядро
теперь отдаёт в PSRAM, внутренняя остаётся для Wi-Fi и TLS.

## Telegram

Бот (`tg.cpp`): уведомления об отключениях сети, низком заряде, аварии,
потере связи с инвертором, сводка в 21:00; команды `/status /today /outages`.
Токен от @BotFather — в «Настройках» или `tg token`; привязка — `/start` и код
со страницы. TLS проверяется по корням Go Daddy G2 и ISRG Root X1. Соединение
не держится: опрос раз в 15 с, после — закрытие.

## Разведка USB инвертора

Сборка `esp32s3-probe` обслуживает разъём USB не опросом, а разведкой
(`usb_probe.cpp`) — для инвертора, про который ничего не известно. Ею
найден протокол HS35. Компьютер к инвертору не поднести, поэтому `lsusb`
делает сама плата: при подключении читает дескрипторы, по ним выбирает мост
(CH34x, CP210x, CDC-ACM или HID) и пробует только запросы чтения — Modbus
регистров 25201…25216 на 19200 и 9600 с адресами 4 и 1, затем текстовые
команды. Ответ Modbus тут же расшифровывается: режим, напряжения батареи,
выхода и сети, мощность, загрузка.

Первая разведка у HS35 (19.10.2026) показала мост CH340 `1a86:7523`, молчание
Modbus на всех вариантах и ответ `NAK` на `QPI` на 9600 — через USB инвертор
говорит текстом, а не Modbus. Поэтому на той скорости, где что-то ответило,
перебирается набор команд-вопросов: PI30 (`QID`, `QPIGS`, `QMOD`…) и диалекты
с `^P` (PI18, PI17); на `NAK` каждая повторяется без контрольной суммы.

**Плата YD-ESP32-S3 требует `flash_mode = dio`.** Её флеш EON не включает QIO,
и после неудачной попытки загрузчика записи и чтения NVS из прошивки молча
теряются: отчёт лежал во флеше, а прошивка его не видела.

Отчёт пишется в NVS по ходу разведки, а не только в конце, и переживает
отключение питания. Читается тремя путями: карточка «Разведка USB инвертора»
сверху дашборда (через точку доступа прямо у инвертора), `GET /api/usb`
и команда `usb` в терминале — уже дома, через разъём COM.

Что нужно у инвертора: переходник OTG USB-C → USB-A в разъём **USB** платы,
кабель USB-A → USB-B до инвертора, питание платы через разъём COM (повербанк)
и замкнутая перемычка **USB-OTG** на обороте платы — без неё на разъём не
идут 5 В, и инвертор подключения не увидит.

## Интерфейс

Два экрана, переключаются кнопкой в шапке.

**Дашборд** — то, ради чего всё затевалось: крупный процент заряда с цветной
полосой (зелёная, жёлтая ниже 40 %, красная ниже 20 %), режим в шапке отдельной
плашкой («заряд 2,43 кВт» / «разряд» / «покой»), напряжение, ток и мощность
крупными цифрами с цветом по направлению тока, сетка ячеек с подсветкой
минимальной и максимальной и отметкой балансировки, температура, разброс,
запас энергии в киловатт-часах и «Защита BMS» — две плашки, «заряд» и «разряд»,
зелёные когда ключи открыты и красные когда BMS ток в эту сторону запретила. Аварии появляются отдельной красной карточкой
и только когда они есть.

**Настройки** — всё, что не нужно человеку, который просто смотрит на батарею:
сеть с поиском доступных, привязка батареи с поиском по эфиру, кнопка «отпустить
батарею приложению», счётчики канала связи, демо-режим.

**Инвертор.** Карточка со схемой потоков мощности: солнце, сеть, инвертор,
нагрузка, батарея. Активные линии подсвечены и анимированы в направлении потока,
разряд батареи идёт против направления заряда и другим цветом. Рядом режим работы
плашкой и таблица значений: питающая сеть, выход, нагрузка, панели, температура,
приоритеты источников. Пока донгл Eybond не привязан, карточка наполняется
демо-режимом — там же моделируется пропадание сети раз в четыре минуты, иначе
индикацию «сеть пропала и вернулась» нечем показать.

**Ярлык на главном экране.** Страница ставится как обычное приложение и
открывается без адресной строки: на iPhone и iPad через «Поделиться» → «На экран
„Домой“» (обязательно в Safari — в Chrome на iOS полноэкранного режима нет),
на Android через меню Chrome → «Добавить на главный экран». Иконка (зелёная
батарея, 192×192 PNG, 695 байт) лежит в PROGMEM и отдаётся по `/icon.png`,
`/apple-touch-icon.png` и `/favicon.ico`; манифест — по `/manifest.json`.
Учтены вырез и статусная полоса через `env(safe-area-inset-*)`; старые браузеры
эту функцию не понимают и берут обычный отступ.

Ярлык ведёт на текущий адрес модуля, поэтому адрес стоит закрепить на роутере —
иначе после смены сети ярлык придётся создавать заново.

Вёрстка консервативная — раскладка на `inline-block` с процентными ширинами, без
CSS-переменных, grid и flex-gap. Исключение сделано для SVG в схеме потоков:
целевое устройство определилось — **iPhone 6 Plus в книжной ориентации** (414 px,
iOS 12, Safari 12), а он рисует и SVG, и CSS-анимации без оговорок.

Сама страница лежит в прошивке **сжатой gzip**: 40 КБ текста превращаются в 12 КБ
флеша, и планшет получает её втрое быстрее. Распаковку делает браузер.

### Во время сканирования модуль ненадолго пропадает

У ESP32 одна антенна. Пока он ищет сети Wi-Fi или устройства Bluetooth, он скачет
по каналам, и HTTP-запрос со страницы в этот момент теряется. Отсюда два правила,
которые пришлось заложить и в прошивку, и в страницу:

* **Ответ уходит до начала сканирования.** Обработчик `/api/wifi/scan` только
  ставит флаг, а сам поиск запускается из `webLoop()`, когда ответ уже отправлен
  и соединение закрыто. Если запускать поиск прямо в обработчике, ответ съедается
  вместе с ним, и страница ждёт его вечно.
* **У опроса есть путь неудачи.** Потерянный запрос — норма, а не ошибка: страница
  повторяет попытку раз в секунду в течение 25 секунд и только потом сдаётся.
  Фоновый секундный опрос состояния на время сканирования приостанавливается,
  чтобы не отнимать эфир.

Так выглядит нормальный обмен: старт отвечает мгновенно, первый опрос теряется,
второй приносит результат.

## Протокол DALY

Донгл DALY — мост BLE ↔ UART, отдающий тот же нативный протокол, что провод:

```
A5 | адрес | DataID | 08 | D0..D7 | CS       CS = младший байт суммы первых 12 байт
```

Адрес отправителя для блютуз-канала — `0x80` (а не `0x40`, который у ПК по UART),
ответ приходит с адресом `0x01`. Сервис `FFF0`, запись в `FFF2`, уведомления из `FFF1`.

Читаются DataID `0x90` (напряжение, ток, SOC), `0x91` (крайние ячейки), `0x92`
(температуры), `0x93` (режим и ключи), `0x94` (конфигурация), `0x95` (напряжения
ячеек, серия кадров), `0x96` (температуры ячеек), `0x97` (балансировка),
`0x98` (флаги аварий).

`dalyParseFrame()` намеренно отделён от транспорта: те же 13 байт придут и по CAN,
и по UART, когда дойдёт очередь до провода — парсер переиспользуется целиком.

## Что ещё не проверено на живой батарее

Смещения полей взяты из протокола DALY v1.2. Их надо сверить с официальным
приложением при первом подключении — прежде всего знак тока, остаточную ёмкость
и нумерацию ячеек в серии кадров `0x95`.

Биты аварий `0x98` показываются сырыми байтами. Подписи к ним появятся после
сверки с приложением: назвать бит неправильно хуже, чем показать шестнадцатеричное
значение.

## API

| Ручка | Ответ |
|---|---|
| `GET /` | страница |
| `GET /api/state` | весь снапшот в JSON |
| `GET /api/ble/release?min=10` | отпустить батарею приложению |
| `GET /api/config?ssid=&pass=&bmsmac=` | сохранить настройки и перезагрузиться |
| `GET /api/sim?on=1` | демо-данные |
| `GET /api/ble/scan` | запустить поиск (5 с, асинхронно) |
| `GET /api/ble/found` | результаты поиска и признак «ещё ищу» |
| `GET /api/ble/bind?mac=…` | привязать батарею и переподключиться, без перезагрузки |
| `GET /api/wifi/scan` | запустить поиск сетей (асинхронно) |
| `GET /api/wifi/found` | список сетей и признак «ещё ищу» |
| `GET /api/events` | журнал событий, новые сверху |
| `GET /api/usb` | отчёт разведки USB и её состояние; только сборки под S3 |

Запись пока без пароля — модуль рассчитан на домашнюю сеть. Перед тем как
добавлять управление инвертором, это надо закрыть.
