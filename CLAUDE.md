# CLAUDE.md — solar-inverter

Прошивка ESP32 для мониторинга инверторов. Начинать с [STATE.md](STATE.md):
что работает, что проверено, что дальше. Что умеет прошивка — в
[firmware/README.md](firmware/README.md), протокол HS35 — в
[HIDEN-HS35.md](HIDEN-HS35.md). Здесь — как работать с кодом и где грабли.
Отвечать владельцу по-русски; он работает с телефона у инвертора, далеко от
компьютера.

## Карта

```
firmware/src/   main · cfg (NVS) · net · web (HTTP API) · stats (LittleFS) · tg (бот)
                weather (прогноз, ночная зарядка) · bootlog · ota · rtc (DS3231) · cli
                schedule (расписание режимов) · battlife (износ) · pace (BMS по RS485)
                inv.cpp + profile_*.cpp (что спрашивать) + inv_usb/inv_ble (провод)
                profile_hs35.cpp — G-ASCII HS35, запись режимов
firmware/web/index.html   страница; scripts/gen_web.py жмёт её в webui_gz.h при сборке
firmware/scripts/ota_upload.py   прошивка по сети тем же путём, что страница
```

## Собрать и залить (HS35)

```bash
cd firmware
~/.platformio/penv/bin/pio run -e esp32s3-hs35
~/.platformio/penv/bin/pio run -e esp32s3-hs35 -t upload --upload-port /dev/ttyACM0   # кабель в COM
python3 scripts/ota_upload.py 192.168.1.117 '<пароль модуля>' .pio/build/esp32s3-hs35/firmware.bin
```

Пароль модуля спрашивать у владельца, в репозиторий не писать. Встала ли
сборка — поле `fw` в `/api/state` (время сборки и коммит). После заливки
плата ~20 с недоступна.

**Платформа** — pioarduino 55.03.311 (Arduino 3.3.11, IDF 5.5.5), прописана
точным релизом в `[common]` `platformio.ini`; все три сборки берут её
оттуда. Под просто `espressif32` на чистой машине встала бы официальная
платформа с Arduino 2.x, а с ней не собираются ни NimBLE 2.x, ни код под
ядро 3.x. Не обновлять платформу «заодно» — только отдельной задачей с
проверкой сборок на живых платах.

## Грабли — каждая стоила времени

* **Флеш только `dio`.** EON на YD-ESP32-S3 не включает QIO, и NVS молча
  теряет запись — настройки «не сохраняются» без единой ошибки.
* **PSRAM** — `-DBOARD_HAS_PSRAM` и `memory_type = dio_qspi`; без флага ядро
  её не ищет. Крупные буферы (`ps_malloc`, длинные String) уходят туда.
* **Serial — на COM-разъёме** (`ARDUINO_USB_CDC_ON_BOOT=0`): нативный USB
  чипа — хост, в нём инвертор.
* **G-ASCII HS35**: байт за байтом с паузой 10 мс; **ответ приходит на
  команду позже**; ответы опознаются по содержимому, очередь отправленного
  сверяется по уникальным ответам, пустые строки пропускать. Подробно —
  HIDEN-HS35.md.
* **Коды режимов** сверены с экраном: OPP 0 GRD · 1 PU · 2 PBG; CHP 0 PV ·
  1 PNG · 2 OPV. Запись — `OPRdd`/`CPRdd` → ACK, затем перечитать. После PBG
  инвертор ~2,5 мин остаётся «от сети» — не откат.
* **Остальные настройки** — таблица `src/hs35_settings.h` (руководство HS35
  + команды ha-eybond-local, проверенные НЕ на HS35). Запись открывается
  только для настройки, которую владелец сверил с экраном (отметка в NVS);
  пределы — по руководству для типа батареи. Не ослаблять эти проверки и
  не добавлять тип батареи, SED, PAM, SON/SOFF в запись.
* **Не экспериментировать с режимами инвертора** без владельца у панели.
  Для проверки записи есть `/opptest` в боте: модуль пишет сам и
  присылает, что видит, человек сверяет с экраном.
* **Память внутренняя впритык.** TLS — один за раз: бот и погода делят
  `tlsLock()`; бот закрывает соединение после каждого опроса. Bluetooth в
  HS35-сборке выключен (`NO_BLE`). Смотреть `heap.min` в `/api/state`.
* **WebServer**: у POST с сырым телом параметры адреса — от прошлого
  запроса, поэтому OTA-кусок несёт смещение и пароль в заголовках. Долгое
  (скан Wi-Fi, переключение) — не в обработчике HTTP, а флагом в `loop()`.
* **Строки в JSON** — только через `jsonEsc`: имя сети с кавычками уже раз
  ломало страницу.
* **Задача бота ≠ loop().** Команды бота ставят флаг, действие — в
  `tgLoop()`/`weatherLoop()`; статистику и её файлы трогает только `loop()`.
* **Время везде UTC+3**, константой (`TZ_SEC`).
* **Формат файлов статистики** (`DayRec` 64 байта и т. д.) — это история
  владельца за год. Поля только в резервных байтах, размер не менять.
* Ключи NVS (`cfg.cpp`) — не длиннее 15 символов.
* Всё, что меняет инвертор, автоматику, бота или прошивку, — под паролем
  модуля (`cfg().webPass`).
* Команды бота, на которые нажимают, — с подчёркиванием (`/opp_pbg`):
  Telegram делает ссылкой только слово до пробела.

## Как проверять

* JS страницы:
  `node -e "const h=require('fs').readFileSync('firmware/web/index.html','utf8');new Function(h.match(/<script>([\s\S]*)<\/script>/)[1])"`.
* Страница на подставных данных — Playwright из
  `/var/www/html/seamless-ach-autotest/node_modules`: `page.route('**/*')`
  отдаёт index.html и JSON вместо `/api/*`; смотреть на ширине 375.
* Живая плата: `/api/state` (всё), `/api/inv` (обмен с инвертором и что
  профиль понял), `/api/events`; на кабеле — команда `status` в терминале.
* Разбор ответов внешних API — сначала на компьютере на настоящем ответе.
