# Разведка: что инвертор говорит по Bluetooth

Инструкция для этапа 0a. Выполняется **без паяльника и без покупок**, за вечер,
и снимает главный риск проекта.

## Зачем это делается

У инвертора есть донгл «Wi-Fi Plug Pro». Штатное приложение ходит к нему через
китайское облако, которое отсюда недоступно, но **по Bluetooth приложение
с донглом разговаривает**. Значит в эфире ходят живые кадры, и по ним можно
ответить на три вопроса:

1. **Есть ли в этом канале телеметрия инвертора** — или там только настройки
   самого донгла (серийник, параметры Wi-Fi)? Если только настройки,
   беспроводного пути к инвертору нет вовсе, и это надо знать до закупки.
2. **На каком языке говорит инвертор** — Modbus RTU или ASCII Voltronic
   (`QPIGS`)? Донгл общается с ним тем же протоколом, который нам нужен
   на RS485.
3. **Какие команды и как часто** шлёт приложение — готовый список того,
   что стоит опрашивать самим.

Ответ на второй вопрос превращает этап 2 из разведки вслепую в проверку
готовой гипотезы.

## Осторожно

* **Не менять в приложении уставки заряда, напряжения и токи.** Снимаем чтение
  и заведомо безобидные действия. Нам нужен протокол, а не эксперимент
  на живой батарее.
* **Лог не публиковать.** В нём могут оказаться серийный номер донгла, пароль
  точки доступа и имя домашней сети. Пришлите файл лично.

## 1. Включить журнал Bluetooth на Android

1. Настройки → «О телефоне» → семь раз нажать «Номер сборки». Появится раздел
   «Для разработчиков».
2. Настройки → Система → Для разработчиков → включить
   **«Журнал HCI-пакетов Bluetooth»** (Enable Bluetooth HCI snoop log).
3. **Выключить и снова включить Bluetooth.** Это обязательно: запись начинается
   с этого момента, без перезапуска лог останется пустым. На части прошивок
   (Xiaomi, Samsung) требуется перезагрузка телефона.

## 2. Снять лог

Порядок важен: чем меньше лишнего в логе, тем легче его читать.

1. Выключить Bluetooth и включить снова — это обнуляет журнал.
2. Открыть приложение инвертора, подключиться к донглу **по Bluetooth**.
3. Делать понятные действия с паузами и **записывать время каждого**:

   | Время | Что сделали |
   |---|---|
   | 12:03:10 | открыл главный экран, ничего не трогаю 30 секунд |
   | 12:03:45 | открыл экран параметров инвертора |
   | 12:04:20 | открыл экран батареи |
   | 12:05:00 | обновил экран вручную |

   Паузы между действиями нужны, чтобы разделить их в логе по времени.
4. Закрыть приложение и выключить Bluetooth.

Этот список действий пришлите вместе с логом — по нему видно, какие кадры
чему соответствуют.

## 3. Достать файл

Путь зависит от прошивки, поэтому надёжнее всего забрать через отчёт об ошибке.

**Через компьютер (нужен adb и включённая отладка по USB):**

```bash
adb devices                      # телефон должен быть в списке
adb bugreport bugreport.zip
unzip -o bugreport.zip -d bugreport
find bugreport -name 'btsnoop*'  # обычно FS/data/misc/bluetooth/logs/
```

**Без компьютера:** Для разработчиков → «Отчёт об ошибке» → «Подробный отчёт»,
дождаться уведомления, поделиться архивом (в облако, себе в мессенджер).
Внутри тот же файл.

**Иногда лежит прямо в памяти телефона** — проверить любым файловым менеджером:
`/sdcard/btsnoop_hci.log` или `/sdcard/Android/data/btsnoop_hci.log`.

## 4. Посмотреть, что внутри

### Быстрый способ — скрипт из этого репозитория

```bash
tshark -r btsnoop_hci.log -Y btatt.value \
  -T fields -e frame.time_relative -e btatt.opcode -e btatt.handle -e btatt.value \
  > att.tsv
python3 scripts/analyze-btsnoop.py att.tsv
```

Скрипт разберёт кадры, отделит записи от уведомлений и попробует опознать
протокол: ASCII Voltronic, Modbus RTU или что-то ещё.

### Вручную в Wireshark

Открыть `btsnoop_hci.log`, в строке фильтра набрать `btatt`.

Что искать:

| Столбец | Что означает |
|---|---|
| Write Request / Write Command | приложение → донгл, это команды |
| Handle Value Notification | донгл → приложение, это ответы |
| Value | сама полезная нагрузка |

### Как опознать протокол по байтам

**ASCII Voltronic** — сразу видно, байты печатаемые:

```
51 50 49 47 53 b7 a9 0d      →  "QPIGS" + CRC16/XMODEM + 0x0D
```

Команды этого семейства: `QPIGS` (текущие показания), `QPIRI` (номиналы),
`QPIWS` (предупреждения), `QMOD` (режим), `POP`/`PCP` (смена приоритетов).
Ответ начинается с `(` и тоже заканчивается `0x0D`.

**Modbus RTU** — короткие бинарные кадры:

```
01 04 20 00 00 25 ...        →  адрес 01, функция 04, регистр 0x2000, 37 слов
```

Признаки: первый байт 1…247 (адрес), второй — `03`, `04`, `06` или `10`,
последние два байта CRC16.

**Только настройки донгла** — если в трафике одни строки вида `PN:...`,
`SSID`, версия прошивки, а телеметрии нет, значит BLE-канал существует ради
первичной настройки сети, и данные ходят только через облако. Тогда
беспроводного пути к инвертору нет, остаётся RS485.

## 5. Что делать с результатом

| Что нашли | Что это меняет |
|---|---|
| Modbus RTU | этап 2 становится реализацией по известной карте регистров; переключение режимов — запись в регистры программ 01 и 16 |
| ASCII Voltronic | реализуем этот диалект: `QPIGS` для показаний, `POP`/`PCP` для смены приоритетов |
| Только настройки донгла | вопрос закрыт, инвертор только по RS485; заодно сэкономлено время на попытках |

В любом случае **основным каналом к инвертору остаётся провод**: протокол
донгла проприетарный, а писать в инвертор через восстановленный из дампов
формат мы не будем — см. принципы в `DOCS.md`.

## Если приложение не подключается по Bluetooth

Оно может требовать входа в аккаунт, а тот — интернета до китайского облака.
Тогда попробовать: включить VPN на время входа, дальше работать по Bluetooth.
Если и это не выходит, посмотреть хотя бы устройство донгла в **nRF Connect**:
приложение покажет список сервисов и характеристик и позволит подписаться
на уведомления. Это не покажет команд штатного приложения, но ответит,
есть ли вообще у донгла характеристика для передачи данных.
