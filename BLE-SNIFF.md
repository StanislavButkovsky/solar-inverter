# Разведка: что инвертор говорит по Bluetooth

Инструкция для этапа 0a. Выполняется **без паяльника и без покупок**, за вечер,
и снимает главный риск проекта.

## Зачем это делается

У инвертора есть донгл «Wi-Fi Plug Pro». Штатное приложение ходит к нему через
китайское облако, которое отсюда недоступно, но **по Bluetooth приложение
с донглом разговаривает**. Значит в эфире ходят живые кадры, и по ним можно
ответить на три вопроса:

1. **Есть ли в этом канале телеметрия инвертора** — или там только настройки
   самого донгла (серийник, параметры Wi-Fi)? Если только настройки,
   беспроводного пути к инвертору нет вовсе, и это надо знать до закупки.
2. **На каком языке говорит инвертор** — Modbus RTU или ASCII Voltronic
   (`QPIGS`)? Донгл общается с ним тем же протоколом, который нам нужен
   на RS485.
3. **Какие команды и как часто** шлёт приложение — готовый список того,
   что стоит опрашивать самим.

Ответ на второй вопрос превращает этап 2 из разведки вслепую в проверку
готовой гипотезы.

## Осторожно

* **Не менять в приложении уставки заряда, напряжения и токи.** Снимаем чтение
  и заведомо безобидные действия. Нам нужен протокол, а не эксперимент
  на живой батарее.
* **Лог не публиковать.** В нём могут оказаться серийный номер донгла, пароль
  точки доступа и имя домашней сети. Пришлите файл лично.

## 1. Включить журнал Bluetooth на Android

1. Настройки → «О телефоне» → семь раз нажать «Номер сборки». Появится раздел
   «Для разработчиков».
2. Настройки → Система → Для разработчиков → включить
   **«Журнал HCI-пакетов Bluetooth»** (Enable Bluetooth HCI snoop log).
3. **Выключить и снова включить Bluetooth.** Это обязательно: запись начинается
   с этого момента, без перезапуска лог останется пустым. На части прошивок
   (Xiaomi, Samsung) требуется перезагрузка телефона.

## 2. Снять лог

Порядок важен: чем меньше лишнего в логе, тем легче его читать.

1. Выключить Bluetooth и включить снова — это обнуляет журнал.
2. Открыть приложение инвертора, подключиться к донглу **по Bluetooth**.
3. Делать понятные действия с паузами и **записывать время каждого**:

   | Время | Что сделали |
   |---|---|
   | 12:03:10 | открыл главный экран, ничего не трогаю 30 секунд |
   | 12:03:45 | открыл экран параметров инвертора |
   | 12:04:20 | открыл экран батареи |
   | 12:05:00 | обновил экран вручную |

   Паузы между действиями нужны, чтобы разделить их в логе по времени.
4. Закрыть приложение и выключить Bluetooth.

Этот список действий пришлите вместе с логом — по нему видно, какие кадры
чему соответствуют.

## 3. Достать файл

Путь зависит от прошивки, поэтому надёжнее всего забрать через отчёт об ошибке.

**Через компьютер (нужен adb и включённая отладка по USB):**

```bash
adb devices                      # телефон должен быть в списке
adb bugreport bugreport.zip
unzip -o bugreport.zip -d bugreport
find bugreport -name 'btsnoop*'  # обычно FS/data/misc/bluetooth/logs/
```

**Без компьютера:** Для разработчиков → «Отчёт об ошибке» → «Подробный отчёт»,
дождаться уведомления, поделиться архивом (в облако, себе в мессенджер).
Внутри тот же файл.

**Иногда лежит прямо в памяти телефона** — проверить любым файловым менеджером:
`/sdcard/btsnoop_hci.log` или `/sdcard/Android/data/btsnoop_hci.log`.

## 4. Посмотреть, что внутри

### Быстрый способ — скрипт из этого репозитория

```bash
tshark -r btsnoop_hci.log -Y btatt.value \
  -T fields -e frame.time_relative -e btatt.opcode -e btatt.handle -e btatt.value \
  > att.tsv
python3 scripts/analyze-btsnoop.py att.tsv
```

Скрипт разберёт кадры, отделит записи от уведомлений и попробует опознать
протокол: ASCII Voltronic, Modbus RTU или что-то ещё.

### Вручную в Wireshark

Открыть `btsnoop_hci.log`, в строке фильтра набрать `btatt`.

Что искать:

| Столбец | Что означает |
|---|---|
| Write Request / Write Command | приложение → донгл, это команды |
| Handle Value Notification | донгл → приложение, это ответы |
| Value | сама полезная нагрузка |

### Как опознать протокол по байтам

**ASCII Voltronic** — сразу видно, байты печатаемые:

```
51 50 49 47 53 b7 a9 0d      →  "QPIGS" + CRC16/XMODEM + 0x0D
```

Команды этого семейства: `QPIGS` (текущие показания), `QPIRI` (номиналы),
`QPIWS` (предупреждения), `QMOD` (режим), `POP`/`PCP` (смена приоритетов).
Ответ начинается с `(` и тоже заканчивается `0x0D`.

**Modbus RTU** — короткие бинарные кадры:

```
01 04 20 00 00 25 ...        →  адрес 01, функция 04, регистр 0x2000, 37 слов
```

Признаки: первый байт 1…247 (адрес), второй — `03`, `04`, `06` или `10`,
последние два байта CRC16.

**Только настройки донгла** — если в трафике одни строки вида `PN:...`,
`SSID`, версия прошивки, а телеметрии нет, значит BLE-канал существует ради
первичной настройки сети, и данные ходят только через облако. Тогда
беспроводного пути к инвертору нет, остаётся RS485.

## 5. Что делать с результатом

| Что нашли | Что это меняет |
|---|---|
| Modbus RTU | этап 2 становится реализацией по известной карте регистров; переключение режимов — запись в регистры программ 01 и 16 |
| ASCII Voltronic | реализуем этот диалект: `QPIGS` для показаний, `POP`/`PCP` для смены приоритетов |
| Только настройки донгла | вопрос закрыт, инвертор только по RS485; заодно сэкономлено время на попытках |

В любом случае **основным каналом к инвертору остаётся провод**: протокол
донгла проприетарный, а писать в инвертор через восстановленный из дампов
формат мы не будем — см. принципы в `DOCS.md`.

## Что уже выяснено про этот донгл

Разбор отчёта с телефона (Huawei ART-L29N, 04.09.2026) дал два факта, которые
меняют весь подход.

**Приложение — `com.eybond.smartclient.ess`, то есть SmartESS от Eybond.**
Значит донгл не «безымянный китайский», а из семейства **Eybond WFBLE.DTU.PlugPro**,
на которое есть открытые руководства. По ним: настройка и отладка идут
**AT-командами** (`AT+VER`, `AT+CLDSRVHOST1=...` и подобные), а в приложении есть
**локальный режим** — кнопка «local mode» на экране входа, которая работает
по Bluetooth **без облака и без входа в аккаунт**.

Отсюда первое, что стоит попробовать: **открыть в SmartESS локальный режим.**
Если он покажет живые показания инвертора, значит телеметрия по Bluetooth ходит,
и вопрос «есть ли она там» закрыт без всякого снифинга.

**Почему журнал HCI оставался пустым.** В отчёте видно строку

```
mSnoopLogSettingAtEnable = empty
```

Android читает настройку `bluetooth_btsnoop_default_mode` **в момент включения
Bluetooth**. На этой прошивке переключатель в меню разработчика её не пишет,
поэтому запись не включалась ни разу — сколько бы раз ни щёлкали тумблер.
Лечится с компьютера:

```bash
adb shell settings put global bluetooth_btsnoop_default_mode full
# затем выключить и включить Bluetooth НА ТЕЛЕФОНЕ (svc bluetooth enable EMUI блокирует)
adb shell dumpsys bluetooth_manager | grep SnoopLog   # должно стать full
```

Только после того, как там появится `full`, снимать лог имеет смысл.

**Донгл в списке сопряжённых устройств:** `DC:0D:30:xx:xx:xx`, имя `979860254651`
— похоже на серийный номер (PN) датлоггера. Этот MAC пригодится, чтобы не искать
устройство в эфире.

## Если журнал снять не удаётся: спросить донгл напрямую

На части телефонов штатный путь закрыт. **Проверено на Huawei ART-L29N,
EMUI 10.1:** переключатель в меню разработчика включается и свойство
`persist.bluetooth.btsnoopenable` действительно становится `true`, но файл
лежит в `/data/misc/bluetooth/logs/`, куда без рута не заглянуть, а в отчёт
об ошибке EMUI его **не кладёт** — проверены три отчёта подряд. Тупик.

Тогда заходим с другой стороны: вместо подслушивания чужого разговора
задаём донглу вопросы сами и смотрим, отвечает ли он.

### Чем

**nRF Connect for Mobile** (Nordic Semiconductor, бесплатно в любом магазине
приложений). Ставится на тот же телефон.

### Как

1. Закрыть официальное приложение — донгл держит одно соединение.
2. В nRF Connect: SCAN, найти донгл (имя вроде `WiFi-Plug`, или сверить
   по MAC с тем, что показывает штатное приложение), CONNECT.
3. Раскрыть список сервисов. Ищем пару характеристик: одну с флагом
   **WRITE** или **WRITE NO RESPONSE**, вторую с **NOTIFY**.
4. У характеристики с NOTIFY нажать значок с тремя стрелками — подписаться
   на уведомления.
5. У характеристики с WRITE нажать стрелку вверх, выбрать формат **BYTE ARRAY**
   и отправить кадр из таблицы ниже. Смотреть, пришло ли что-то в NOTIFY.

### Что отправлять

**Начать с AT-команд.** Донгл Eybond настраивается именно ими, они простой текст
без контрольных сумм, и ответ приходит сразу. Формат: команда, затем `\r\n`.

| Команда | Байты | Что спрашивает |
|---|---|---|
| `AT` | `41 54 0D 0A` | «ты жив?», ответ `OK` |
| `AT+VER` | `41 54 2B 56 45 52 0D 0A` | версия прошивки донгла |
| `AT+WEBU` | `41 54 2B 57 45 42 55 0D 0A` | адрес облачного сервера |

Если пришёл `OK` или любой текст — интерфейс опознан, и дальше уже понятно,
куда копать. Команды на запись (`AT+...=значение`) **не отправлять**: настройки
донгла нам менять незачем.

Дальше — кадры самого инвертора. Они уже с контрольными суммами, вставлять как есть.

**Диалект Voltronic (ASCII).** Начинать с `QPI` — самая безобидная команда,
она просто спрашивает версию протокола:

| Команда | Что спрашивает | Байты |
|---|---|---|
| `QPI` | версия протокола | `51 50 49 BE AC 0D` |
| `QID` | серийный номер | `51 49 44 D6 EA 0D` |
| `QMOD` | текущий режим работы | `51 4D 4F 44 49 C1 0D` |
| `QPIGS` | все текущие показания | `51 50 49 47 53 B7 A9 0D` |
| `QPIRI` | номиналы и уставки | `51 50 49 52 49 F8 54 0D` |
| `QPIWS` | предупреждения | `51 50 49 57 53 B4 DA 0D` |

Ответ начинается с `(` и заканчивается байтом `0D`. Если пришло — вопрос
закрыт, инвертор говорит на Voltronic.

**Диалект Modbus RTU.** Если на ASCII молчит:

| Что | Байты |
|---|---|
| функция 03, регистр 0x0000 | `01 03 00 00 00 01 84 0A` |
| функция 04, регистр 0x0000 | `01 04 00 00 00 01 31 CA` |
| функция 03, регистр 0x2000 | `01 03 20 00 00 01 8F CA` |
| функция 04, регистр 0x2000 | `01 04 20 00 00 01 3A 0A` |

Ответ начнётся с `01 03` или `01 04`. Ошибка тоже полезна: `01 83` или `01 84`
означают «регистра нет», но **сам протокол угадан верно**.

### Как понимать результат

| Что вышло | Вывод |
|---|---|
| ответил на ASCII | инвертор говорит на Voltronic, реализуем этот диалект |
| ответил на Modbus, хоть бы и ошибкой | инвертор говорит на Modbus RTU |
| молчит на всё, но характеристики есть | донгл не прозрачный мост, а своя прошивка со своим протоколом — беспроводного пути нет, только RS485 |
| нет характеристики с WRITE | канал только на чтение настроек, телеметрии там нет |
| ответил на `AT` | это управляющий канал донгла; телеметрия может идти отдельной характеристикой — смотреть, что приходит в NOTIFY само по себе |

Снимок экрана nRF Connect со списком сервисов пришлите в любом случае —
по нему видно устройство донгла, даже если он промолчит.

### Ещё вариант: другой телефон

Штатный журнал HCI нормально работает на Pixel, Samsung и Xiaomi — там он
попадает в отчёт об ошибке. Если под рукой есть не-Huawei, снять лог на нём
проще, чем гадать по ответам.

## Если приложение не подключается по Bluetooth

Оно может требовать входа в аккаунт, а тот — интернета до китайского облака.
Тогда попробовать: включить VPN на время входа, дальше работать по Bluetooth.
Если и это не выходит, посмотреть хотя бы устройство донгла в **nRF Connect**:
приложение покажет список сервисов и характеристик и позволит подписаться
на уведомления. Это не покажет команд штатного приложения, но ответит,
есть ли вообще у донгла характеристика для передачи данных.
